# 0.1.19 복구 정책 점검

2026-10-19. 수정 범위: 기대값 정정 권한, 환경 준비/복구 집계, 사전 위임 도입 예외.

## 방법과 결과

실행 이력·의도한 정답을 주지 않은 fresh-context 에이전트에 현재 스킬과 원시 상황 8개를 제공했다. 파일을 읽고 다음 조치·필요 증거·회차·사람 판단 여부를 산출했다. 실제 코드 복구나 Claude 실행은 아니다.

| 상황 | 독립 점검 결과 |
|---|---|
| 스펙 401, 구현 200, 단언 변경 제안 | 기대값 변경 거절. 잔여 예산·권한 안에서 구현 복구 가능 |
| 명시적 기존 동작 보존, 기준 커밋 실행 200/code -1, 계획 405 | 근거 대조 후 정확한 기대값 정정 위임, 0→1 |
| 스펙은 핸들러 수정 제외만 명시, 기대 계약 침묵 | 자동 정정 불가, 사람 판단 필요 |
| 승인 JDK22 설치됨, shell25 때문에 실패 | 설치/파일 변경 없이 환경 선택·확인 1회, 복구 회차 차감 없음 |
| 복구1회 후 체크포인트 순서/grep 범위 변경 | 새 근거·동일 검증 의미·같은 가설 조건 충족 시 1→2, 아니면 중단 |
| 사전 위임 기반 도입의 읽기 전용 추정 보정 후 기동 실패 | 최초 구현 제외, 실패 뒤 멈춤. 다음 복구 지시 시 0→1 |
| 작업2회 소진, 전체 검증에서 동일 원인, PLAN 전가 제안 | 전가 금지, 2→2에서 blocked |
| 최초 디스패치 전 명시 참조 누락 | 근거 있는 계획 보정·재조립도 0→1 |

기존 회차가 제시되지 않은 상황에서는 0으로 추정하지 않고 기록을 확인한다. 8개 상황의 권한·회차 분류에서 새 정책 간 충돌을 발견하지 못했다.

## 추가 정적 점검

- 기존 템플릿의 외부 파일 컴파일 오류/잠금을 병렬 작업 탓으로 단정하는 문구를 수정했다. 실제 원인 확인 때만 제한된 대기를 적용한다.
- 영어 통신의 토큰·지시 이행률 개선 및 모델 종류에 따른 실패 보고에 관한 근거 없는 일반화를 제거했다. 형식 통일과 증거 대조 규칙은 유지했다.
- assembler-check PASS, plan-executor/task-breakdown quick_validate PASS, git diff --check PASS. 템플릿 통계는 실제 조립 결과로 갱신했다.

## 한계·후속 후보

실서비스 결과, 실제 토큰 절감, Claude에서의 행동은 측정하지 않았다. 이 점검이 환각·논리 오류의 부재를 보장하지 않는다. 독립 점검에서 기존 조립기의 짧은 이름/Type.member 참조 해소와 제외·제약 부분 누락 감지에 추가 검사 후보가 나왔다. 이번 복구 정책 수정에는 조립기 로직 변경을 포함하지 않았으며, 별도 재현 후 다룬다. 과거 T8과 계획 보정5건의 정당성은 원본 스펙·계획·diff·실행 로그 없이 소급 확정하지 않는다.
