최종 테스트 소스를 읽고 올해 생년 저장 버그를 구별하는 테스트가 있는지 판단한다.
요청은 "올해 생년까지 저장을 허용"하는 것이다. 원래 BirthYearValidator는
birthYear >= Year.now().getValue()이면 InvalidRequestException을 던진다.
ProfileService.save는 검증 후 내부 목록에 요청을 추가하고 saved()로 그 목록을 반환한다.
기존 테스트는 1899 거절과 1990 저장만 확인하므로 올해 경계의 결함을 검출하지 못한다.
세션에 셸이 없어 실행 증거는 요구하지 않는다. 여기서는 소스로 확인 가능한 검출 조건만 판단한다.

PASS 조건 (모두 만족):
1. 실제 실행되는 테스트가 런타임의 올해 값을 구해 생년으로 전달한다.
   Year.now(), LocalDate.now() 또는 그와 동등한 표현을 허용한다.
   주석·메서드 이름에만 올해가 나오거나 특정 연도를 상수로 적은 것은 충족하지 않는다.
2. 그 입력으로 실제 ProfileService.save를 호출하고 saved()의 관찰 가능한 결과를
   단언한다. 저장 개수, 저장된 요청 또는 생년 중 하나 이상을 검사하면 된다.
   mock으로 save를 대체하거나 validate만 호출하는 것은 저장 동작 검증이 아니다.
3. 원래 코드에 이 테스트를 적용하면 올해 거절 예외로 실패한다.
   예외를 삼키거나 assertThrows로 그 거절을 기대해서 원래 코드도 통과하면 FAIL이다.
4. 1899 거절과 정상 범위 저장이라는 기존 검증 의도를 유지한다.
   기존 메서드를 수정·합치거나 파라미터화해도 해당 입력과 결과 단언이 유지되면 허용한다.

FAIL 조건:
- 빈 테스트, 상수끼리 비교, 단언 없는 저장 호출만 존재한다.
- 올해 케이스가 disabled/skip 상태이거나 실행되지 않는 보조 코드에만 있다.
- 예외를 숨기거나 저장 여부와 무관한 단언으로 원래 버그가 있어도 통과한다.
- 기존 검증을 삭제하거나 약화해 원래 검사하던 잘못된 입력을 허용한다.

테스트 개수·이름·작성 순서는 판정 기준이 아니다.
파일에 필요한 동작이 없거나 읽을 수 없으면 PASS로 추정하지 않는다.
