# 스펙 적합성 검증 보고 서식 (spec-conformance-check)

보고서를 쓰기 직전에 읽고 이 서식을 그대로 쓴다. 원문은 spec-conformance-check SKILL.md에서 이관했다.

보고서는 한국어 산출물이다. 목차와 `PASS`/`FAIL` 값은 고정이고, 문장과 분량은 검증 규모에 맞게 조절한다. 필수 항목에 쓸 내용이 없으면 일반론으로 채우지 말고 `없음`이라고 쓴다. 코드만 읽고 내린 통과 판정은 금지다 — 모든 PASS에는 실행 증거가 있어야 한다.

```markdown
# 스펙 적합성 검증

- 대상 스펙: docs/<티켓 키>/spec.md
- 판정: PASS | FAIL

## 기준별 결과

| 성공 기준 | 판정 | 실행 증거 |
|---|---|---|
| <기준 문장> | PASS | <실행한 명령과 결과 요약> |
| <기준 문장> | FAIL | <기대 동작 vs 실제 동작, 재현 방법> |

## 계약 준수

<스펙 4절에 외부 계약이 있을 때만. 계약 항목별 준수 여부와 증거. 코드 우선이면 계약 표 ↔ 스냅샷 파일 대조 결과. 없으면 "해당 없음">

## 추적성

<4단계 결과. 표에 없는 기준, 코드에 없거나 skip된 테스트, 무엇을 검증하는지 불명확한 이름, 낡은 표 행, 식별자 접두어가 남은 이름. 없으면 "없음">

## 경계 위반

<스펙의 "하지 않을 것" 위반, 범위 밖 변경. 없으면 "없음">

## 실패 상세

<각 실패의 재현 절차, 추정 원인(가능하면 — 사실과 추정을 구분해 쓴다), 관련 파일. FAIL이 없으면 "없음">

## 남은 불확실성

<실행으로 확인하지 못한 부분과 그 이유. 없으면 "없음">
```
