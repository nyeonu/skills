# 사용자 보고 서식 (plan-executor 5절)

plan-executor가 실행을 마치고 사용자에게 보고할 때 이 서식을 그대로 쓴다. 본문 판단 규칙(테스트 대조 원칙, 미작성·미커버 분기 처리)은 SKILL.md 5절에 있다.

**사용자 보고는 한국어 산출물이다** (채널 언어 정책의 예외 아님 — 원칙 그대로다). 결과부터 쓴다 — 과정 서술은 판정에 필요한 만큼만 남긴다. 필수 항목에 쓸 내용이 없으면 일반론으로 채우지 말고 `없음`이라고 쓴다.

```markdown
## 실행 결과

- 계획: <계획 문서 경로>
- 완료한 작업: <완료 T-N 목록 / 전체 개수. 재시도나 tier 상향이 있었으면 함께 적는다>
- 브리프: <작업별 한 줄 — 브리프 파일 첫 줄 통계 + `결과(1회차 PASS | 재시도 n회 | 승격 | blocked)` + `계획 이탈(없음 | 내용)`. 계획 이탈은 PASS와 별도로 적는다 — 통과했어도 계획이 지정한 것을 바꿨으면 이탈이다>
- 바뀐 파일: <경로 목록>
- 판정: <전체 검증 통과 여부>
- 자동 복구: <작업별 사용 회차/2 · 원인 · 계획 보정 · 검증 결과 · 중단 사유. 참조 처리 보정(표기 보정·재조립, 브리프 누락 보완)이면 재발 여부를 함께 — 현재 계획의 `## 복구 기록`에 같은 유형이 둘 이상이면 재발, 비교할 기록이 없으면 `이전 이력 확인 불가`. 보정 없이 발견한 누락·오인식도 사실로 적는다. 없으면 없음>

## 검증

| 검증 항목 | 실행한 명령 | 결과 |
|---|---|---|
| T1 검증 | npm test -- src/auth | PASS |
| 전체 검증 | npm test | PASS |

## 테스트 대조

| 계획한 테스트 (출처/층) | 스펙 기준 | 실제 테스트 (파일 · 테스트 이름) | 결과 |
|---|---|---|---|
| birthYear가 1900 미만이면 400으로 거절한다 (②/유닛) | 잘못된 생년월일은 거절한다 | ProfileValidationTest · "birthYear가 1900 미만이면 400으로 거절한다" | PASS |
| PUT 실패 시 upsert가 롤백된다 (③/통합) | 저장 실패 시 이전 값이 유지된다 | 미작성 | — |

- 추적성 표 갱신: <계획 표와 실제 이름이 달라 갱신한 행. 없으면 "없음">
- skip·비활성화된 테스트: <0건이어야 정상. 있으면 목록과 사유>
- 신규·변경된 테스트 파일: <목록>
- 커버리지 증감: <레포가 추적하는 경우만. 감소했으면 원인>

## 남은 문제

- 실행하지 못한 검증: <없으면 "없음">
- 미커버 분기: <실행자 보고 취합. 계획에 없던 오류 분기·엣지 케이스. 없으면 "없음">
- 다시 판단할 조건: <이 판정이 무효가 되는 전제 변화. 참조 처리 재발(불필요한 표기 보정 반복·브리프 누락 재발·같은 참조 오류 재발)이 확인되면 관련 작업·기록 위치와 함께 `검증 확장 필요`를 적는다 — 다음 조치는 재발 입력을 `evals/assembler-check` 회귀에 추가하고 추출 문제인지 확인·전달 문제인지 좁히는 것. 없으면 "없음">

## 다음 단계

스펙 적합성 검증(spec-conformance-check)을 진행한다.
```

- "다음 단계"는 생략하지 않는다. 여기서의 검증은 "계획대로 됐는가"까지이며, "스펙에 맞는가"는 별도 단계다.
