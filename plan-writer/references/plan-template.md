# PLAN.md 템플릿

아래 구조를 그대로 사용한다. `<>` 부분만 채우고 섹션 구조는 유지하라.
frontmatter는 기계 파싱용이므로 유효한 YAML이어야 한다.

```markdown
---
plan_id: <kebab-case-id>            # 예: 2026-07-06-session-token-refresh
title: <계획 제목>
status: draft                        # draft | approved | in_progress | done
author: <작성 에이전트/사람>
created: <YYYY-MM-DD>
target: <대상 저장소 또는 디렉터리>
tasks:                               # 본문 작업 섹션과 1:1 대응
  - id: T1
    title: <작업 제목>
    depends_on: []                   # 예: [T1, T2]
    status: pending                  # pending | in_progress | done | blocked
    tier: standard                   # standard(기본) | light — 작업 성격 기반 실행 등급
                                     # standard: 판단·추론이 필요한 작업 / light: 명세가 완전한 기계적 작업
                                     # 실제 모델 매핑은 실행 플랫폼이 결정 (플랫폼 중립 필드)
  - id: T2
    title: <작업 제목>
    depends_on: [T1]
    status: pending
    tier: light
---

# <계획 제목>

## 1. 목표 (Goal)

<이 작업이 왜 필요한지, 완료되면 무엇이 달라지는지 1~3문장.
실행자가 모호한 상황에서 판단할 때의 기준이 된다.>

## 2. 배경 및 현재 상태 (Context)

<실행자가 알아야 할 코드베이스 현황. 관련 파일 경로, 핵심 함수/클래스,
기존 컨벤션, 관련 이슈/PR 링크. 실제로 확인한 사실만 쓴다.>

## 3. 판단 근거 (Rationale)

<왜 이 접근 방식을 선택했는지. 검토했던 대안과 채택하지 않은 이유,
감수한 트레이드오프. 사용자가 이 계획을 승인할지 판단하는 근거가 된다.>

## 4. 범위 (Scope)

**포함:**
- <이번 계획에서 하는 것>

**제외 (하지 말 것):**
- <건드리지 말아야 할 것. 예: "기존 API 시그니처 변경 금지", "리팩토링 금지">

## 5. 작업 목록 (Tasks)

### T1: <작업 제목>

- **대상 파일**: `<경로>` (실재하는 경로만)
- **작업 내용**: <무엇을 어떻게 구현할지 단계별로. 사용할 기존 함수/패턴 명시.>
- **완료 기준 (Acceptance)**:
  - <검증 가능한 조건. 예: "만료 토큰으로 요청 시 401 반환">
- **검증 방법 (Verify)**:
  ```bash
  <실행 가능한 명령. 예: npm test -- src/auth>
  ```
- **주의사항**: <함정, 엣지 케이스, 하지 말 것>

### T2: <작업 제목>
<동일 구조 반복. depends_on이 있으면 첫 줄에 "T1 완료 후 시작" 명시.>

## 6. 전체 검증 (Final Verification)

<모든 작업 완료 후 통합 확인 방법. 예: 전체 테스트, 빌드, E2E 시나리오.>

## 7. 리스크 및 롤백 (Risks)

<예상 리스크와 문제 발생 시 되돌리는 방법. 없으면 "없음">
```

## 작성 시 체크리스트

- [ ] frontmatter `tasks`와 본문 `### T*` 섹션이 1:1 대응하는가
- [ ] 모든 파일 경로를 실제로 확인했는가
- [ ] 각 작업의 verify가 실행 가능한 명령인가
- [ ] 제외 범위(하지 말 것)를 명시했는가
- [ ] 판단 근거에 대안과 트레이드오프를 기록했는가
- [ ] 각 작업에 tier를 지정했는가 (light로 내린 작업은 근거가 있는가)
- [ ] 저장 경로가 `docs/plan/YYYY-MM-DD-<주제>.md` 형식인가
- [ ] 코드베이스를 처음 보는 에이전트가 이 문서만으로 작업 가능한가
